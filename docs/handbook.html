00

What this app does

You describe a property — city, locality, size, age, furnishing, amenities — and the app returns two things: a predicted market price from a model trained on comparable listings, and a plain-language investment insight written by an LLM (or a rule-based template when no AI key is configured). A scatter plot places the property against similar listings so the number isn't a black box.

Is this real data? No.

The 4,000 listings it's trained on are synthetically generated (a formula-based script, not real transactions or scraped listings). So the ₹2.27 Cr the app prints for a given input is not a real Mumbai market price — it's the model correctly reproducing the pattern we built into the fake data. The 0.95 R² proves the ML pipeline works, not that the price is accurate. See §03 for the full explanation and how to plug in real data.

The three moments that matter

1 Fill the form

Nine inputs, all constrained — you can't submit a 40-bedroom shack or negative square footage. Bad inputs are rejected before they reach the model.

2 Read the price

Formatted the way Indian listings actually read prices: Lakhs under a crore, Crores above — or in USD, if you've switched the sidebar currency toggle.

3 Read the reasoning

A short paragraph explaining why — amenities, age, furnishing — plus a scatter chart of similar listings so you can eyeball whether the number is reasonable.

Beyond a single prediction

The app is organized into five tabs, not one form:

01 Valuation

The form above — price, confidence range, price/sqft, AI insight, and a comparable-listings chart.

02 Market Insights

Dataset-wide view: listing counts, median price and area, average price by city, price-vs-area scatter, and a price-by-furnishing comparison.

03 Financing

A loan/EMI calculator — down payment, interest rate and tenure sliders compute monthly EMI, total interest, and total payment, pre-filled from your last valuation.

04 History

Every valuation run this session, kept client-side in the browser.

05 Documents

The RAG feature (§02) — upload a property document or ask a question against the sample documents already indexed, and get a sourced answer.

Sidebar tools

The sidebar stays out of internal plumbing (no raw config or model internals) and instead offers working tools: an INR/USD currency toggle that reformats every price on the page, a city snapshot lookup (median price and price/sqft for any covered city, pulled live from the dataset via /market/by-city), and a unit converter (sqft ↔ sq.m ↔ acre).

Why a separate API instead of calling the model straight from the frontend

A React app could theoretically ship a model in the browser via ONNX, but that means retraining every UI change and duplicating logic. It talks to FastAPI over HTTP instead because that's the shape a real product takes: the model (and vector store) can be redeployed, scaled, or swapped for a different framework without touching the UI, and the same endpoints can serve a future mobile app or another frontend untouched.

03

The model

Trained on data/housing_data.csv — 4,000 synthetic listings across seven Indian metros, generated with deliberate correlations (bigger area, more amenities, newer builds → higher price, with locality-level premiums) so the regression problem is realistic rather than random noise.

Honest limitation

This is not trained on real transaction data. Treat the R² and error figures as evidence the pipeline works correctly, not as a claim about real Indian property markets. Swapping in a real listings CSV with the same column names is a drop-in replacement — see §06.

Feature set

FeatureTypeNotes
area_sqftnumericbuilt-up area, 100–20,000 sqft
citycategoricalMumbai, Delhi, Bangalore, Pune, Hyderabad, Chennai, Ahmedabad
localitytextfree-text neighbourhood
bedrooms / bathroomsnumeric0–10
age_yearsnumeric0–100
furnishingcategoricalUnfurnished / Semi / Fully
parkingnumeric0–5 spots
amenities_scorenumeric0–10 composite score

Training procedure

Two candidate regressors are cross-validated (5-fold) on an 80/20 split, and the better one is kept:

ModelCV R² (mean)CV R² (std)Selected
Random Forest0.9482±0.0041—
Gradient Boosting0.9542±0.0036✓

Held-out test set (800 rows): R² 0.9511 · MAE ≈ ₹14.7 Lakh · RMSE ≈ ₹20.6 Lakh. Preprocessing is a single sklearn Pipeline — standard-scaled numerics, one-hot encoded categoricals — saved together with the model so there's no train/serve skew.

src/train.py

CANDIDATES = {
    "random_forest": RandomForestRegressor(n_estimators=300, random_state=42),
    "gradient_boosting": GradientBoostingRegressor(
        n_estimators=300, learning_rate=0.05, max_depth=3, random_state=42
    ),
}
# 5-fold CV on each → keep the higher mean R² → fit on full train split
# → evaluate on held-out test set → joblib.dump() the winning pipeline

Document Q&A (RAG)

Separate from the price model: a retrieval-augmented generation pipeline that answers questions against a small library of property-related documents, using LangChain for chunking/orchestration and ChromaDB as the vector store.

DocumentContent
locality_guide_mumbai_pune.mdfictional neighbourhood guide, Mumbai & Pune localities
locality_guide_bangalore_hyderabad.mdfictional neighbourhood guide, Bangalore & Hyderabad localities
sample_home_sale_agreement_template.mdgeneric sale-agreement template (no real names)
buyers_legal_checklist_india.mdstamp duty, RERA registration, title verification, home-loan documents
amenities_society_rules_brochure.mdgeneric society rules / amenities brochure

Pipeline: src/ingest_documents.py chunks each file (RecursiveCharacterTextSplitter, 800 chars / 120 overlap), embeds the chunks, and persists them to app/vectorstore/chroma/. At query time, /documents/chat embeds the question, retrieves the closest chunks, and either hands them to an LLM (if OPENAI_API_KEY is set) or returns the top chunk verbatim with a clear "retrieved excerpt, not synthesized" label — the same graceful-degradation philosophy as /insights.

Works with zero API keys

Embeddings default to a free, local model (sentence-transformers/all-MiniLM-L6-v2 via langchain-huggingface) when no OpenAI key is set — downloaded once from Hugging Face, then fully offline. Set OPENAI_API_KEY to switch to OpenAI embeddings and get LLM-synthesized answers instead of raw retrieved text.

Fictional documents, not legal advice

All five sample documents are invented for this project — no real addresses, people, or legally binding content. The legal checklist in particular should not be treated as authoritative guidance.

Request

  "city": "Mumbai",
  "locality": "Andheri",
  "bedrooms": 2,
  "bathrooms": 2,

Response

{
  "predicted_price": 22700000.0,
  "predicted_price_formatted": "₹2.27 Cr",
  "currency": "INR",
  "model_name": "GradientBoostingRegressor"
}

Generate an investment insight

POST /insights

Same body as /predict, plus the predicted_price you just received. If OPENAI_API_KEY is set, an LLM writes the paragraph; otherwise a rule-based template fills in cleanly — the field never breaks, it just gets less clever.

{
  "insight": "This 2BHK in Andheri, Mumbai is estimated at ₹2.27 Cr (~₹18,925/sqft)…",
  "source": "template"   // or "llm" when OPENAI_API_KEY is configured
}

Ask a question against indexed documents

POST /documents/chat

Request

{
  "question": "What documents does a buyer need for a home loan?",
  "history": []
}

Response

{
  "answer": "...",
  "sources": ["buyers_legal_checklist_india.md"],
  "source_type": "llm"   // or "template" without an API key
}

Upload and list documents

POST /documents/upload

Multipart form upload, field name file — accepts PDF or plain text/markdown. Chunks and indexes it into the same ChromaDB collection immediately.

{"filename": "my_document.pdf", "chunk_count": 4, "source_type": "uploaded"}
GET /documents

Lists every indexed document (sample and uploaded) with its chunk count.

Market data endpoints

Power the sidebar and Market Insights tab — computed live from data/housing_data.csv with pandas, not hardcoded.

GET /market/summary

Dataset-wide stats: listing count, median price/area, cities covered, average price by city, price by furnishing.

GET /market/by-city/{city}

Per-city snapshot: median price, median price/sqft, top-priced locality.

GET /health

Returns {"status":"ok","model_ready":true} — checks the model artifact exists without loading it.

GET /docs

Swagger UI, generated automatically from the Pydantic schemas in app/schemas.py.

05

Frontend

A Vite + React + TypeScript single-page app in frontend/. It calls the API with fetch through a typed client (frontend/src/api/client.ts) and reads the API's address from the build-time env var VITE_API_BASE_URL, defaulting to http://localhost:8000. Financing-tab EMI math and unit conversion run client-side; everything else — predictions, insights, document Q&A, market stats — comes from the API.

Styling is a single global stylesheet (frontend/src/index.css) implementing the same professional, icon-free theme throughout — plain typography and text labels, no emoji or pictogram icons, light/dark support via prefers-color-scheme.

Why this matters locally

If something else on your machine already occupies port 8000 (a container runtime, another API), run the backend on a different port and set VITE_API_BASE_URL in frontend/.env before starting the dev server — no code changes needed. Same idea if port 5173 (Vite's default) is already taken by another project: pass --port <n> to npm run dev.

06

Running it locally — step by step

Ten steps, in order. Each one ends with something you can check before moving to the next — don't skip the checks, they're where problems actually surface.

Step 1 · Prerequisites

You need Python 3.10–3.13, Node.js 18+, and Git. Confirm before anything else:

python --version     # should print 3.10.x – 3.13.x
node --version       # should print v18.x or higher
git --version

Step 2 · Get the code

git clone https://github.com/ramabharti8/AI-Real-Estate-Advisor.git
cd AI-Real-Estate-Advisor

Step 3 · Create a virtual environment and install backend dependencies

# Windows (Git Bash)
python -m venv venv
source venv/Scripts/activate
pip install -r requirements.txt

# macOS / Linux
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt

Verify your terminal prompt starts with (venv) and pip install ends with no red error text. Expect 3–8 minutes on a fresh machine — the RAG stack (torch, sentence-transformers) is a large download.

Windows: torch import fails after install

If sentence-transformers pulls a torch version that fails to import with a shm.dll / WinError 126 error, reinstall the CPU-only build explicitly: pip install torch==2.6.0 --index-url https://download.pytorch.org/whl/cpu. See §09 Q9.

Step 4 · Generate the dataset and train the model

python src/generate_data.py
python src/train.py

Expect console output ending with something like:

Selected model: gradient_boosting
Test MAE:  1,468,817
Test RMSE: 2,064,111
Test R2:   0.9511

Saved model -> app/model/model.joblib
Saved metrics -> app/model/metrics.json

Verify data/housing_data.csv and app/model/model.joblib now exist. Without the model file, the API responds with a 503 on /predict.

Step 5 · Ingest the RAG documents

python src/ingest_documents.py

Chunks and embeds the five sample documents in data/documents/ into a local ChromaDB store at app/vectorstore/chroma/. On first run this also downloads the local embedding model (~90 MB, one-time, offline afterward).

Verify the script prints something like Done. 5 document(s), 22 chunk(s) indexed. — re-run any time after changing files in data/documents/; it's idempotent.

Step 6 · Start the backend API

uvicorn app.main:app --reload --port 8000

Leave this terminal running. Verify open localhost:8000/health in a browser — it should show {"status":"ok","model_ready":true}. Also try localhost:8000/docs for the interactive API playground.

Port already in use?

Something else on your machine (Docker, another app) may already hold port 8000. Run on a different port instead: uvicorn app.main:app --reload --port 8010 — then set VITE_API_BASE_URL in Step 8 to match.

Step 7 · Install frontend dependencies (open a second terminal)

cd frontend
npm install

Verify no error at the end and a node_modules/ folder appears. Takes 1–2 minutes.

Step 8 · Start the frontend

npm run dev
# if the API isn't on the default port:
# create frontend/.env with VITE_API_BASE_URL=http://localhost:8010

Verify a browser tab opens at localhost:5173 with the Valuation form. Fill it in, click Run Valuation — you should see a price, confidence range, and an insight paragraph. Check the Documents tab too and ask a question — you should get an answer with sources.

Port 5173 already in use?

Common if another Vite project is running. Use a different port: npm run dev -- --port 5180.

Optional · Turn on real AI features

Without this, /insights and /documents/chat still work — they use a template and raw retrieval instead of an LLM.

cp .env.example .env
# open .env and set:
OPENAI_API_KEY=sk-...

Restart the API (Step 6) after adding the key. /insights's "source" and /documents/chat's "source_type" will switch from "template" to "llm".

Optional · Run the test suite and confirm the frontend build

pytest -q
# 11 passed — training artifacts, /predict, /insights, and the RAG endpoints

cd frontend && npm run build
# produces frontend/dist/ -- what a static host would serve
Daily workflow, once set up

You only repeat Steps 4–5 when the data, model, or documents change. Day to day it's just: activate venv → Step 6 in one terminal → Step 8 in another.

07

Training on a real dataset

Everything so far uses synthetic data (§03). This walks through replacing it with a real, downloaded dataset end to end — download, clean, retrain, and compare the new model's accuracy against the synthetic baseline.

Reference dataset

These steps target Kaggle's "Bengaluru House Price Data" (amitabhajoy/bengaluru-house-price-data) — one of the most widely used open Indian housing datasets, ~13,000 real listings. Any other CSV works too; you'll just adjust the column mapping in Step 3.

Step 1 · Get a Kaggle account and API token

Create a free account at kaggle.com if you don't have one. Then: Account → API → Create New Token. This downloads a kaggle.json file containing your credentials.

# place it where the Kaggle CLI expects it
mkdir -p ~/.kaggle
mv ~/Downloads/kaggle.json ~/.kaggle/kaggle.json
chmod 600 ~/.kaggle/kaggle.json     # Git Bash / macOS / Linux

On plain Windows PowerShell, copy it to C:\Users\<you>\.kaggle\kaggle.json instead — no chmod needed.

Step 2 · Download the dataset

pip install kaggle
mkdir -p data/raw
kaggle datasets download -d amitabhajoy/bengaluru-house-price-data -p data/raw --unzip

Verify data/raw/Bengaluru_House_Data.csv now exists. No Kaggle CLI access? Download the ZIP manually from the dataset's Kaggle page and extract it to the same path.

Any other dataset works too

Looking for other real listings? Kaggle's search for "India house price" or "real estate India" turns up several — MagicBricks scrapes, city-specific listings, etc. Column names will differ; adjust Step 3 accordingly.

Step 3 · Convert it to this project's schema

The model expects nine specific columns (§03's feature table). Real listings datasets rarely match that exactly — the Bengaluru dataset, for instance, has no age, furnishing, or amenities columns. src/prepare_real_data.py handles the conversion and is explicit about every value it has to invent:

python src/prepare_real_data.py --input data/raw/Bengaluru_House_Data.csv --city Bangalore

What it does, column by column:

Target columnSourceHandling
area_sqfttotal_sqftparses ranges ("2100-2850") and unit suffixes (sq. meter, acre, cent, guntha)
bedroomssizeextracts the leading digit from "4 BHK" / "4 Bedroom"
bathroomsbathdirect, coerced to numeric
localitylocationcleaned text
pricepriceKaggle stores this in Lakh INR — multiplied by 100,000
age_yearsnot presentimputed: random 0–14 years
furnishingnot presentimputed: random, weighted toward Unfurnished
parkingbalconyproxied from balcony count, not a real parking figure
amenities_scorenot presentimputed: random, centered at 6.0/10

Verify the script prints row counts and its imputation summary, then writes data/housing_data.csv — overwriting the synthetic file. Back it up first if you want to keep both: cp data/housing_data.csv data/housing_data_synthetic.csv before running Step 2.

Step 4 · Retrain

python src/train.py

Same command as §06 Step 4 — it always trains on whatever is currently at data/housing_data.csv.

Step 5 · Compare against the synthetic baseline

Read the new app/model/metrics.json against the synthetic numbers from §03. Expect the real-data R² to be noticeably lower — commonly 0.6–0.8 instead of 0.95. That drop is the honest answer to "does this work on real data": real prices depend on factors this feature set doesn't capture (exact floor, view, builder reputation, negotiation), and three of the nine features are imputed noise rather than signal. A lower, real R² is more trustworthy than a high, synthetic one.

Step 6 · Test predictions against known listings

Pick a few rows straight out of data/raw/Bengaluru_House_Data.csv, run them through /predict, and compare the model's number to the listing's actual price:

curl -X POST http://localhost:8000/predict -H "Content-Type: application/json" -d '{
  "area_sqft": 1056, "city": "Bangalore", "locality": "Electronic City Phase II",
  "bedrooms": 2, "bathrooms": 2, "age_years": 5, "furnishing": "Semi-Furnished",
  "parking": 1, "amenities_score": 6.0
}'
# compare against that row's real price (39.07 Lakh in the raw file)

Restart the API (§06 Step 6) after retraining so it picks up the new model file — it's loaded once at startup, not per request.

Before you trust the numbers

This pipeline is a learning exercise in going from raw data to a served model, not a licensed valuation product. Even with real prices, the imputed age/furnishing/amenities columns mean predictions should be treated as ballpark estimates, not appraisals.

08

Deployment

Backend and frontend deploy as two separate services — the split from §02 pays off here directly. Two paths are documented: a fast managed-PaaS route, and a fuller Google Cloud Platform walkthrough. Neither has actually been deployed yet — this is a reference for when you're ready, not a record of something already live.

01 API → Render / Railway

render.yaml, Procfile and runtime.txt are already in the repo. Render builds from the Procfile's uvicorn app.main:app command; the training step runs at build time so the model artifact is always fresh.

02 UI → Vercel / Netlify

The React app in frontend/ builds to static files (npm run build → frontend/dist/) — drop that into any static host. Set VITE_API_BASE_URL at build time to your deployed API's URL.

Full step-by-step for this route, including environment variables and health-check paths, is in docs/DEPLOYMENT.md.

Deploying to Google Cloud Platform — step by step

A more hands-on path: the API runs as a container on Cloud Run (serverless, scales to zero), the React build is served as static files, and secrets live in Secret Manager rather than in code. This section explains exactly how — follow it when you're ready to actually deploy.

Step 1 · Prerequisites

# Install the gcloud CLI, then:
gcloud auth login
gcloud projects create ai-real-estate-advisor --set-as-default
gcloud config set project ai-real-estate-advisor
gcloud services enable run.googleapis.com artifactregistry.googleapis.com \
  secretmanager.googleapis.com cloudbuild.googleapis.com

Billing must be enabled on the project — Cloud Run has a free tier, but the project still needs a billing account attached.

Step 2 · Store the OpenAI key in Secret Manager

printf "%s" "sk-your-key-here" | gcloud secrets create OPENAI_API_KEY --data-file=-

Nothing sensitive ever touches the repo or the container image this way — Cloud Run injects it as an environment variable at runtime.

Step 3 · Containerize the backend

Add a Dockerfile at the project root:

FROM python:3.11-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY . .
RUN python src/generate_data.py && python src/train.py && python src/ingest_documents.py
CMD exec uvicorn app.main:app --host 0.0.0.0 --port ${PORT:-8080}

Running the training and ingestion scripts at build time means the image is self-contained — no separate step to populate the model or vector store after deploy.

Step 4 · Build and push the image

gcloud artifacts repositories create app-images --repository-format=docker --location=asia-south1
gcloud builds submit --tag asia-south1-docker.pkg.dev/ai-real-estate-advisor/app-images/api:latest

Step 5 · Deploy the backend to Cloud Run

gcloud run deploy real-estate-api \
  --image asia-south1-docker.pkg.dev/ai-real-estate-advisor/app-images/api:latest \
  --region asia-south1 \
  --allow-unauthenticated \
  --memory 1Gi \
  --set-secrets OPENAI_API_KEY=OPENAI_API_KEY:latest

Verify the command prints a service URL — open <url>/health in a browser to confirm it responds.

The vector store is ephemeral here

Cloud Run containers are stateless between deploys — anything written to disk at runtime (e.g. a document uploaded through /documents/upload after launch) disappears on the next cold start or redeploy. The sample documents survive because they're baked into the image at build time (Step 3). For uploads to persist permanently, mount a Cloud Storage volume at the ChromaDB persist path, or swap ChromaDB for a managed vector store.

Step 6 · Build and host the React frontend

cd frontend
VITE_API_BASE_URL=https://real-estate-api-xxxxx.run.app npm run build
gcloud storage buckets create gs://real-estate-advisor-ui --location=asia-south1
gcloud storage buckets update gs://real-estate-advisor-ui --web-main-page-suffix=index.html
gcloud storage cp -r dist/* gs://real-estate-advisor-ui

Point that bucket behind Cloud CDN (or use Firebase Hosting instead of raw Cloud Storage — same idea, less manual CDN wiring) for a proper HTTPS URL and caching.

Step 7 · Allow the frontend to call the backend

Add the frontend's origin to allow_origins in the CORS middleware in app/main.py, rebuild, and redeploy (Steps 3–5).

Step 8 · Optional — custom domain and continuous deployment

  • Custom domain: gcloud run domain-mappings create --service real-estate-api --domain api.yourdomain.com, plus a CNAME/A record with your DNS provider.
  • CI/CD: a Cloud Build trigger on pushes to main re-runs Steps 4–5 automatically — set one up from the Cloud Build console pointed at the GitHub repo, using the same Dockerfile.
Before you deploy — either path

Set OPENAI_API_KEY as a secret on the hosting platform, never in the repo. .env is already gitignored — keep it that way. This walkthrough is intentionally not executed against a live GCP project as part of this handbook — running it will incur real cloud costs, however small.

09

Troubleshooting — errors and answers

Every error below was actually hit while setting this project up on Windows. Each entry shows the exact message, why it happens, and the fix.

Q1 python -m venv venv fails with "Unable to copy … venvlauncher.exe"
Unable to copy 'C:\...\venv\scripts\nt\venvlauncher.exe' to
'E:\AI-Real-Estate-Advisor\venv\Scripts\python.exe'

Cause: a venv folder already exists at that path, and its python.exe is locked — usually because a server (uvicorn, or a background pip install) started from that same environment is still running and holding the file open.

Fix: stop whatever is using that interpreter, then delete and recreate the folder.

Get-Process python -ErrorAction SilentlyContinue | Stop-Process -Force
Remove-Item -Recurse -Force venv
python -m venv venv
Q2 Remove-Item -Recurse -Force venv fails with "Access to the path … is denied"
Remove-Item : Cannot remove item ...\charset_normalizer\cd.cp313-win_amd64.pyd:
Access to the path 'cd.cp313-win_amd64.pyd' is denied.

Cause: .pyd files are native DLLs. Once a Python process imports one, Windows keeps a lock on it for as long as that process is alive — even -Force can't override an OS-level file lock, only a permissions problem.

Fix: find the process still holding the venv open and end it, then retry the delete.

wmic process where "name='python.exe'" get ProcessId,CommandLine
taskkill /PID <pid-using-this-venv> /F
Remove-Item -Recurse -Force venv
Q3 source venv/Scripts/activate — "term 'source' is not recognized"
source : The term 'source' is not recognized as the name of a cmdlet,
function, script file, or operable program.

Cause: source is a Bash/Git-Bash command. Windows PowerShell has no equivalent named command — it activates a venv by dot-invoking a .ps1 script instead.

Fix — pick the one matching your terminal:

# PowerShell
.\venv\Scripts\Activate.ps1

# Git Bash
source venv/Scripts/activate

# cmd.exe
venv\Scripts\activate.bat
Q4 Activate.ps1 is blocked by execution policy
... cannot be loaded because running scripts is disabled on this system.

Cause: PowerShell's default execution policy blocks unsigned local scripts, and the venv activator is one.

Fix: allow scripts for this process only — no admin rights needed, and it doesn't change the policy permanently.

Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\venv\Scripts\Activate.ps1
Q5 uvicorn app.main:app --port 8000 — "[WinError 10013] An attempt was made to access a socket in a way forbidden by its access permissions"
ERROR:    [WinError 10013] An attempt was made to access a socket in a
way forbidden by its access permissions

Cause: port 8000 is already claimed by another process on the machine — in this environment, Docker Desktop's background service (com.docker.backend.exe) binds it. Windows refuses the second bind rather than sharing it.

Fix: run the API on a free port instead, and point the frontend at the same port.

uvicorn app.main:app --reload --port 8010

# create frontend/.env with:
VITE_API_BASE_URL=http://localhost:8010

To find what's actually holding a port before changing anything: netstat -ano | findstr :8000, then tasklist /FI "PID eq <pid>" to identify it.

Q6 /predict or /insights returns {"detail":[{"type":"missing", ...}]}
{"detail":[{"type":"missing","loc":["body","locality"],
"msg":"Field required", ...}]}

Cause: this is not a bug — it's FastAPI/Pydantic validating the request body and rejecting it because a required field (here, locality) was left out. See §04 for the full required-field list.

Fix: include every field from the schema. The fastest way to get a correct example body is /docs, which lets you fill and send a real request from the browser.

Q7 GET /health or /docs returns {"detail":"Not Found"} even though the server "started"

Cause: the request reached a different server already listening on that port — not this app. Two servers cannot share one port, so whichever bound it first answers, and it has no route matching this app's paths.

Fix: confirm which process actually owns the port (Q5's commands), and run this app on a port nothing else holds.

Q8 npm run dev starts, but the app at localhost:5173 is a different project entirely

Cause: another Vite project on your machine is already using port 5173 (Vite's default) and answered first — this project's dev server either failed to bind, or is running on a different port than you assumed.

Fix: check the terminal output for the actual port Vite chose, or force one explicitly:

npm run dev -- --port 5180
Q9 After pip install -r requirements.txt, importing the app fails with a shm.dll / WinError 126 error from torch
OSError: [WinError 126] The specified module could not be found.
Error loading "...\torch\lib\shm.dll" or one of its dependencies.

Cause: sentence-transformers (used for the free local embedding fallback) pulls in a default torch build via PyPI that doesn't import cleanly on some Windows setups.

Fix: reinstall the CPU-only build explicitly from PyTorch's own index:

pip uninstall -y torch
pip install torch==2.6.0 --index-url https://download.pytorch.org/whl/cpu

This download is large (a few hundred MB) — expect several minutes even on a fast connection.

Q10 /documents/chat works, but every answer is a raw excerpt instead of a written answer

Cause: not a bug — this is the documented no-API-key fallback path (§03 RAG). Without OPENAI_API_KEY, the endpoint returns the most relevant retrieved chunk verbatim rather than calling an LLM to synthesize a response, and labels it as such ("source_type": "template").

Fix: set OPENAI_API_KEY (§06, optional step) and restart the API to get synthesized answers instead.
